# 图床页面设计 QA

本文档保留图床页面的视觉和交互验收重点。

## 页面目标

图床是高频上传工具，而不是复杂后台页面。

页面优先级：

1. 上传；
2. 当前目标 Source；
3. 上传结果/链接复制；
4. 历史图片；
5. Token/高级设置进入设置页。

## 布局

- 主内容居中；
- 不额外增加无意义右侧栏；
- 上传区是页面视觉中心；
- 空状态不伪造图片或统计；
- 没有可用 Storage Source 时显示明确空状态和下一步；
- 用户不需要看到 Source ID、真实路径、挂载路径等内部信息。

## 上传状态

必须覆盖：

- idle；
- drag-over；
- uploading；
- success；
- partial failure（未来批量上传时）；
- error。

## 历史墙

- 缩略图统一比例；
- 原图懒加载；
- 删除/复制链接操作不抢占图片主体；
- 回收站图片不展示；
- 空状态保持简洁。

## 移动端

- 上传仍为第一入口；
- 历史墙减少列数；
- 操作菜单可触控；
- 不依赖 hover 才能使用核心操作。

## 与 1.1 / 1.2 的关系

统一 Upload Task Manager 完成后，图床可以复用任务状态组件，但不强制把普通文件上传和图床业务语义合并。

统一 Preview Resolver 完成后，历史墙大图查看可以复用 Image Renderer。
