# 产品定义

本文档定义 OmniStore 长期面向谁、解决什么问题，以及哪些事情明确不是产品目标。版本级功能范围请查看 [`ROADMAP.md`](ROADMAP.md) 与 [`roadmap/`](roadmap/)。

## 1. 产品定位

OmniStore 是一款**以本地真实目录为数据源**的轻量级自部署存储中心，面向个人、家庭和小团队。

它在本地文件系统之上提供统一的：

- 私有网页文件管理器；
- 公开网盘；
- 文件/目录分享；
- WebDAV；
- S3 兼容访问；
- 图床；
- 用户、Policy、配额、文件台账、搜索和回收站；
- 审计、恢复与运维能力。

OmniStore 的价值不是“提供最多的存储协议”，而是：

> 文件始终是用户自己可理解、可直接接触的真实文件；OmniStore 负责安全、权限、访问入口和生命周期管理。

核心抽象始终保持：

```text
Storage Source = 本地真实目录
```

## 2. 目标用户

主要用户：

1. 在自有服务器、NAS、家庭服务器上管理文件的个人。
2. 家庭成员之间共享部分存储空间的家庭环境。
3. 需要简单权限划分和多协议访问的小团队。

主要角色：

- 超级管理员：实例、用户、Policy、存储源、协议凭据与运维。
- 普通用户：使用被授权的目录和功能。
- 匿名访客：仅访问管理员/用户明确公开的网盘、分享或匿名图床入口。

## 3. 产品原则

### 3.1 安静的文件柜

界面清爽、可靠、克制。常用动作直接可见，低频设置不占用主要注意力。

### 3.2 真实文件优先

文件系统是真实数据源。SQLite 保存系统状态、权限、台账、Token、分享、图床流水和审计，但不构造一套取代真实文件系统的虚拟对象存储。

### 3.3 可解释

用户应知道：

- 当前在哪个存储源；
- 自己拥有什么权限；
- 操作会作用到哪个真实路径；
- 删除是否可恢复；
- 分享、公开和私有访问的边界。

### 3.4 轻量部署

长期保持：

```text
单体 Go 服务
+ SQLite
+ 本地文件系统
+ 嵌入式 React 前端
```

不为理论扩展性引入额外基础设施。

### 3.5 可靠性优先于花哨能力

上传、覆盖、移动、复制、回收站、Multipart 等写操作必须优先保证：

- 路径安全；
- 权限正确；
- 配额一致；
- 崩溃后可恢复；
- 不删除来源不明的数据。

## 4. 当前稳定能力

`1.0.0` 已建立完整基础：

- 本地存储源；
- 用户与 Policy；
- 子路径权限；
- 用户/来源配额；
- 文件台账与 Reconcile；
- 同源和跨源复制/移动；
- 回收站；
- 分享；
- 搜索；
- WebDAV；
- S3 + Multipart；
- 登录/匿名图床；
- 缩略图缓存；
- 审计；
- 系统配置包导出；
- 关键写路径 Crash Recovery；
- 统一 Release Gate。

详细历史范围见 [`archive/1.0/ROADMAP.md`](archive/1.0/ROADMAP.md)。

## 5. 永久非目标（Non-goals）

下面不是“当前版本暂不实现”，而是 OmniStore 的长期产品边界。

### 5.1 不把远程服务作为 Storage Source

不支持：

- S3 后端存储源；
- WebDAV 后端存储源；
- SMB 后端存储源；
- 其他远程网盘作为底层源。

原因：当前安全、锁、quota、journal、rename/fsync、scan/reconcile 和 symlink 语义均建立在本地真实文件系统之上。

### 5.2 不做新的存储引擎

不做：

- Chunk Storage；
- CAS；
- 内容寻址存储；
- 文件去重；
- 对象版本控制；
- 文件历史版本。

### 5.3 不做同步盘

不提供官方 Dropbox/OneDrive 式同步客户端，不定义本地端与服务端的双向同步、冲突合并或镜像删除协议。

### 5.4 不做分布式/企业基础设施

不做：

- 集群；
- 多节点；
- 多副本并发管理同一数据；
- Redis；
- PostgreSQL；
- 消息队列；
- 微服务拆分。

### 5.5 不做在线办公/复杂媒体平台

不做：

- Office 在线编辑；
- 多人协作编辑；
- 服务端 FFmpeg 媒体转码平台；
- 媒体库刮削和媒体服务器体系。

浏览器天然支持的图片、文本、PDF、音视频预览可以作为轻量文件体验继续增强。

### 5.6 不做插件系统

OmniStore 保持明确、可维护的核心能力，不把产品演变成通用插件运行时。

## 6. 版本策略

`1.0.0` 是基础能力稳定版。

`1.x` 开始采用“小而明确的产品主题”持续发布：

- `1.1`：文件体验；
- `1.2`：预览与分享；
- `1.3`：运行与管理；
- `1.4`：备份与恢复；
- `1.5`：生态兼容。

Epic 是长期产品方向，不等于必须塞入同一个版本。
