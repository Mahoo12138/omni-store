## 2. Site Capability 设置

后台：

```text
系统设置
└── 站点配置
    ├── 站点服务
    │   ├── 公开网盘
    │   ├── 快速图床（匿名上传、图片保留策略）
    │   └── 文件中转
    └── 通用配置（品牌信息、运行信息、配置导出）
```

每项：

- enabled；
- Storage Source；
- capability-specific settings。

不要把这些开关留在 Source 卡片中。

两个 Tab 使用 outline 样式。服务绑定通过配置弹窗保存，匿名上传开关即时保存，图片保留策略独立保存；不把多个独立 API 包装成一次统一保存。换源仅影响图床新上传和中转新任务，历史数据保留原定位。

## 4. Transfer UX

实现基线（2026-10-05）：公开入口 `/transfer` 与登录工作台 `/app/transfer` 复用 `TransferWorkspace`，主任务保持一致。取件和收集链接直接进入 `/pickup/{publicKey}` 与 `/collect/{publicKey}`。

### 空间与导航

公开中转、取件和收集页复用深色 masthead / hero：品牌与公开导航在顶部，页面标题、说明和服务状态在下方。宽白色 workbench 与 hero 形成前后层次；工作区外层不加描边，主表单不拆成一层层嵌套卡片。登录工作台沿用 AppShell，并复用同一工作区。

三个主 Tab 为「发送文件」「收集文件」「收发记录」，默认发送文件。主 Tab 和设置内的子 Tab 均沿用共享 outline 样式。桌面创建区将主表单与设置并列，设置默认折叠；窄屏改为纵向排列，导航、Tab 和操作按钮可换行，长标题与文件路径在容器内换行。

### 创建与任务详情

- 发送主表单展示发件包标题、说明和文件选择区，支持选择文件、整个文件夹及拖入；登录用户还能从已有网盘文件创建快照。「发送设置」内按「基础」「文件」分组，配置有效期、可选访问密码、取件码及下载次数上限。点击「发送文件」依次创建草稿、上传文件、定稿。
- 收集主表单展示收集任务标题与说明。「收集设置」内按「基础」「收集信息」「文件」分组，配置有效期、可选访问密码、收件码、提交者姓名与备注要求，以及文件类型、单文件和总量上限。点击「生成收集链接」完成创建。
- 创建成功结果留在当前表单内，展示可直接打开的链接、复制入口、二维码和记录入口。取件码或收件码默认关闭；启用后短码仅在首次创建结果显示一次，历史记录不重新显示。
- 收发记录分为「我发送的」「我收集的」。任务详情与收件箱在工作区内独立展开，包含状态、文件或提交列表及操作，不通过任务详情弹窗再嵌套收件箱。二维码和网盘文件选择器仍使用 Dialog。
- 发送草稿详情保留上传文件、上传文件夹、从已有文件添加、定稿和撤销入口。收件箱按提交展示姓名、备注、时间、文件数量与大小，支持逐文件下载；登录用户还能保存到自己的网盘。

### 身份与公开访问

访客与登录用户均可创建发件包和收集任务。访客通过同一浏览器中的 Cookie 保持身份，刷新后仍能管理自己的记录；访客身份及任务具有有限有效期，任务有效期不能超过身份期限，也不提供永不过期选项。网盘快照和保存到网盘操作仅对登录用户开放。

公开链接默认直接展示取件或上传内容。创建者选择短码或访问密码后，接收方才需要解锁；字段只显示实际启用的保护方式。服务状态在入口可见；新任务服务不可用时禁用创建，已有取件链接仍按原有效期和授权访问。

### 状态与恢复

发送和收集面板通过 `keepMounted` 保留各自表单状态，切换 Tab 不丢失标题、说明和已选文件。身份切换时清理上一身份的中转缓存；身份确认失败时不显示旧身份的记录。

部分上传成功后保留成功项、失败项和草稿，提供「重试未完成文件」及「继续编辑草稿」，重试只处理尚未完成的文件。公开收集的校验或网络失败也保留文件、姓名和备注，允许移除问题文件后继续提交。写入期间禁用主 Tab、详情返回及冲突操作，上传完成前不能定稿。

记录详情使用 `view=history&record=send|collect&id=…` 深链接，刷新页面仍可回到同一任务。「刷新记录」同时更新任务状态与对应的草稿文件或收件箱；关闭收集后，已有提交仍保留在记录中。

## 7. 静态资源服务界面

后台功能服务有三项：公开网盘、快速图床、文件流转中心。存储源列表将名称与状态、可换行的真实路径、配额与协议摘要、操作分层呈现，窄屏自然重排。「配置」弹窗分为「访问协议」与「存储设置」；静态 HTTP 在访问协议中展开，提供发布目录选择、baseUrl 复制、媒体范围说明、cache/CORS、公开范围确认和重绑维护入口，独立保存静态策略；文件管理复用普通文件管理器。

普通用户有发布目录权限时可在文件管理器看到公开状态与直链复制；没有权限不能因为协议存在就看到私有配置。协议按源管理，不意味着为每个用户增一套发布配置。

图床文案改为“快速图床”，匿名/登录表示上传身份；不得把公开图片标成私密。匿名保留期在选择文件前和上传结果都可见，不使用含混“临时”二字代替失效日期。

表单修改源/发布根须进入 reset/relocate 流程；长缓存需确认；关闭公开盘不应把静态资源面板一起置灰。内部 URL 的 404 是网络响应要求，不是单纯设计一个错误页。
