## 1. 信息架构

2.0 主导航建议：

```text
文件
最近
收藏
图床
分享

管理（管理员）
```

Public Drive 是公开侧入口，不需要在登录主导航重复成为另一个 Source Browser。

公开侧导航基线（2026-10-06）：网盘、图床、公开浏览、分享和关于页复用 `PublicNavigation`，固定顺序为「公开网盘、匿名图床、账号入口」。账号入口按登录状态显示「管理登录」或「进入工作台」。全部按钮共用 32px 高度、14px 图标、10px 水平内边距、描边、圆角、间距与键盘焦点样式，当前入口通过 `aria-current="page"` 高亮。深浅背景仅调整颜色，窄屏使用同一换行规则。「关于我们」在公共页底部提供统一入口。

## 2. Site Capability 设置

后台：

```text
系统设置
└── 站点配置
    ├── 站点服务
    │   ├── 公开网盘
    │   └── 快速图床（匿名上传、图片保留策略）
    └── 通用配置（品牌信息、运行信息、配置导出）
```

每项：

- enabled；
- Storage Source；
- capability-specific settings。

不要把这些开关留在 Source 卡片中。

两个 Tab 使用 outline 样式。服务绑定通过配置弹窗保存，匿名上传开关即时保存，图片保留策略独立保存；不把多个独立 API 包装成一次统一保存。换源仅影响图床新上传，历史数据保留原定位。

## 3. Source 设置

Source 详情：

```text
基本信息
路径与配额
排除规则
协议
  WebDAV
  S3
  静态 HTTP
```

协议页面显示：

- Human Name；
- Endpoint；
- Stable Key / Bucket；
- Copy button。

不要要求用户记随机 key。

全站标签页与列表/网格/画廊视图切换统一使用 outline 样式：每个选项有独立描边，选中项使用品牌蓝描边和浅蓝背景，不使用下划线或填充底轨样式。共享样式在 `web/src/components/ui/Tabs.css.ts`，选中状态由 `data-active`、`aria-selected` 或 `aria-pressed` 驱动。

## 5. 静态资源服务界面

后台功能服务有两项：公开网盘、快速图床。存储源列表将名称与状态、可换行的真实路径、配额与协议摘要、操作分层呈现，窄屏自然重排。「配置」弹窗分为「访问协议」与「存储设置」；静态 HTTP 在访问协议中展开，提供发布目录选择、baseUrl 复制、媒体范围说明、cache/CORS、公开范围确认和重绑维护入口，独立保存静态策略；文件管理复用普通文件管理器。

普通用户有发布目录权限时可在文件管理器看到公开状态与直链复制；没有权限不能因为协议存在就看到私有配置。协议按源管理，不意味着为每个用户增一套发布配置。

图床文案改为“快速图床”，匿名/登录表示上传身份；不得把公开图片标成私密。匿名保留期在选择文件前和上传结果都可见，不使用含混“临时”二字代替失效日期。

表单修改源/发布根须进入 reset/relocate 流程；长缓存需确认；关闭公开盘不应把静态资源面板一起置灰。内部 URL 的 404 是网络响应要求，不是单纯设计一个错误页。

## 6. 表格操作栏（2026-10-30）

所有表格最后一列的操作栏只放图标，不再放文字按钮。

- 每个图标操作必须有 `aria-label`，并用 Fluent `Tooltip` 说明语义；鼠标悬停与键盘聚焦都要出现提示。禁止只依赖原生 `title`。
- 管理后台表格统一使用 `web/src/components/ui/IconAction.tsx`：32×32 命中区、幽灵按钮外观；破坏性操作使用 `danger`，并排在操作组最后。
- 行尾「更多」菜单同样使用图标触发器，并带 Tooltip；展开后的菜单项继续用文字。
- 文件表格、回收站和公开分享文件表沿用同一语义；紧凑行操作可保留既有命中区尺寸，但必须包裹 Tooltip。
- 图标语义固定：编辑=铅笔、删除=垃圾桶、配额=仪表、台账校准=同步、更多=省略号。
- 本条不适用于页面级主操作（新建、上传、保存）、批量操作条和弹窗确认按钮；这些地方继续使用文字按钮。

## 7. 文案：只写功能，不写解释（2026-10-31）

界面文案只服务于操作、约束与风险，不替用户理解界面。禁止新增下列解释性文案：

- 页面、卡片或弹窗标题下的功能性副标题：重述标题、复述控件选项或按钮动作。
- 系统行为自述：如“立即生效”“自动同步到账号”“换设备后仍然保持”“记录不会丢失”“会出现在这里”。
- 空态解释：如“上传后会出现在这里”“点击右上角开始”；空态只保留状态标题和可执行动作。
- 建议性、说服性文案：如“建议使用字母数字符号组合”“便于后续撤销”；除非是安全或兼容要求。
- 为显而易见字段写用途说明，如“说明策略适用的人群或用途”。

允许且必须保留的只有四类：

1. 约束：格式、长度、取值范围、默认值、单位、上限、访问端点；
2. 风险：不可恢复、配额与权限影响、会话/缓存/公开范围后果；
3. 安全与一次性：Token、Secret 仅显示一次，公开读取范围；
4. 恢复：错误原因、具体下一步、必需的操作顺序。

判定方法：删掉这句话后，用户是否仍能完成操作且不产生误解？能，则删。

实现约束：

- `PageHeader.description` 只接受用户或任务自带的说明（存储源描述等），不再放页面介绍。
- `SectionCard.hint` 只放计数或上述四类信息，不写功能简介。
- 空态不写“会出现在这里”类描述；没有可执行动作的空态应补一个下一步按钮，而不是补一段说明。
- `DialogWrap.description` 在标题已经表达动作时不复述；正文只写后果、约束或字段。
- 公开产品介绍页（`About`）的产品叙事不按操作界面约束，但不得用它替代操作说明；同一页面内的控件仍适用本条。
