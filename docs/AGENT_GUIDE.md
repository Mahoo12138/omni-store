# Agent 开发规则

参与项目的 Agent 在修改代码前应阅读本文件，并结合相关架构、功能和验收文档工作。

## 给编码模型的硬性禁止事项

编码时不得做以下事情：

1. S3 与 Multipart 属于 `1.0.0 / V1`，不要扩展出路线图和 S3 功能文档之外的协议半成品。
2. `s3_enabled=false` 时不要启动 S3 端口；S3 只允许显式启用独立监听。
3. 不要使用 GORM。
4. 不要引入 Redis。
5. 不要引入消息队列。
6. 不要实现复杂 RBAC。
7. `1.0.0 / V2` 的子路径权限只允许在访问策略内使用显式子路径规则，并遵循“源级默认权限 + 最长路径前缀覆盖”，不要扩展为文件级 ACL 或复杂 RBAC。
8. 不要把存储源子路径当成新存储源规避权限。
9. 不要维护完整虚拟文件树。
10. 不要把所有文件写入 SQLite。
11. 不要用 xattr 或 sidecar 文件污染用户目录。
12. 不要直接写最终上传路径。
13. 不要在上传未完成时覆盖原文件。
14. 不要允许路径穿越。
15. 不要跟随 symlink。
16. 不要把系统数据目录挂载成存储源。
17. 不要把删除存储源实现成删除真实文件。
18. 不要让普通用户管理存储源。
19. 不要让匿名用户使用 WebDAV。
20. 不要让 PicGo Token 调用普通文件管理 API。
21. 不要把登录密码当 WebDAV 密码。
22. 不要记录明文密码或 Token。
23. 不要开放宽松 CORS。
24. 分片上传、回收站、文件复制、跨来源移动、缩略图与配额均属于 `1.0.0`；实现时必须遵循各自文档和统一的路径安全、权限、锁与台账约束。
25. `1.0.0` 不支持多实例。
26. 不要通过调高 Vite 的 `chunkSizeWarningLimit` 掩盖前端单包过大；页面必须按路由懒加载，第三方组件优先使用稳定子路径导入。

## 核心实现心智模型

编码时始终遵循这条路径：

```text
识别访问主体
-> 鉴权
-> 将不透明路由 key 或 public_mount_path 解析为内部 storage_source_id
-> 找到存储源
-> 检查存储源状态
-> 检查权限
-> 规范化相对路径
-> 禁止路径穿越
-> 检查排除规则
-> 检查 symlink
-> 获取路径锁
-> 操作真实文件系统
-> 写数据库记录或审计日志
-> 返回统一响应
```

任何入口都不能绕过这条链路。

入口包括：

1. REST 文件 API。
2. 私有网页文件管理器。
3. 公开网盘。
4. WebDAV。
5. 登录用户图床。
6. 匿名公共图床。
7. `1.0.0 / V1` 的 S3 基础对象操作与 Multipart。

## 结论

OmniStore 的 `1.0.0 / V1` 先把本地存储源、访问策略、公开网盘、私有文件管理、WebDAV、图床和 S3 打通，并确保路径安全、权限一致、上传可靠、审计可追踪。

`V1`、`V2` 只是 `1.0.0` 的两个内部阶段。V2 的 Policy 子路径规则、文件台账与扫描、来源和用户配额、复制与跨来源移动、分享、回收站、搜索与索引全部属于首发阻断项；未实现或未验收的能力不得伪装成已支持，也不得提前发布 `1.0.0`。

`1.0.0` 成功的标准不是功能多，而是路线图范围内每条路径都稳定、安全、可解释，并且不会污染用户目录、误删真实文件或制造协议半成品。
