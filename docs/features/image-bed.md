# 快速图床（匿名 / 登录上传）

> 修订：2026-09-29 / R2。2.0 目标规范；未标为基线的内容不代表已实现。

状态：2.0 目标规范。博客按路径托管图片、视频改由 [静态资源托管](static-assets.md) 负责；登录用户仍可使用快速图床。

## 1. 产品行为

用户上传受支持图片，立即得到 `/i/{image_id}.{ext}` 直链。公开访问不需要登录；登录状态决定上传授权、图片归属和历史记录，不决定图片是否私密。

图床全站绑定一个源。普通用户不选源、不指定内部路径。匿名入口默认关闭，由管理员显式启用；登录用户使用图床功能并不因此获得 backing Source 的普通文件读写权限。

管理入口为「系统设置 → 站点配置 → 站点服务 → 快速图床」；绑定与服务开关、匿名上传开关、图片保留策略各自保存。判断能否启用匿名上传使用图床服务绑定状态，不使用匿名上传关闭时会清空的公开目标字段。实例运行信息统一放在「通用配置」。

## 2. 存储与记录

新图存入绑定源的 `.omnistore/image-bed/`。图片 ID、归属、source/path 和公开状态由图片业务记录管理，公开 URL 不等于磁盘路径。通用 REST、公开盘、静态资源、Share、WebDAV/S3、搜索都不能直接读取该内部目录。

保留图片计费需要的 file_records 时，使用 `resource_scope=image_bed`；它是内部台账，不进入普通搜索/最近/收藏。用户和源的计费各计算一次，不把 images 与 file_records 累加两次。[数据模型](../DATA_MODEL.md) 定义作用域。

只有图床服务可以根据图片 ID 读取托管内容。底层通过范围受限的内部读写接口复用锁、配额、journal 和安全校验，不提供客户端可控的 bypass 参数。

## 3. 内容与原始文件

沿用已实现的服务端图片校验和大小限制；不要只信扩展名、客户端 MIME，也不要为未验证的解码器承诺格式支持。新图片不允许借主动内容执行同源脚本；历史格式按现有安全隔离读取或附件降级。

视频走静态资源，不增加匿名任意文件上传。图床原图与可重建缩略图保持分离。

## 4. 匿名保留与管理

“临时需要直链”不是默认七天删除。2.0 图片默认不自动过期；管理员可以为未来匿名上传设置独立保留天数。提交前显示策略，上传结果返回 `expires_at`（永久时 null）。新策略只作用于新图，既有失效时间不被静默追溯修改。

匿名不等于没有配额：必须有限流、并发限制、单文件/每日或窗口用量限制、站点可用容量检查。管理员可查阅、撤下或删除匿名图片；匿名者不拥有所有图片列表或删除权。不要凭知道公开 image_id 授予删除能力。

登录用户保留命名 Token、个人历史、撤销和删除流程。PicGo 继续返回实际直链，不向客户端要求 source key。

## 5. 启停、Rebind 与旧图片

为避免重配上传位置破坏历史博客链接，图床 enabled/binding 控制入口及新上传；既有 `/i/` 根据图片记录和其 source 状态读取，不以“必须在当前绑定源”判定有效。全站撤下既有公开图片是独立、明确且有审计的维护动作，不通过清空绑定隐式执行。

Rebind 只影响新图，旧记录保留真实定位，阻止删除仍被旧图片引用的 Source。旧普通目录图片不因这次文档更新被自动移动进 `.omnistore/`。静态资源路径不会从随机 ID 反向猜测；迁移要求见 [2.0 迁移](../design/v2-migration.md)。

## 6. 删除与缓存

删除必须处理图片业务记录、台账、文件和缓存，使用可恢复步骤；不是直接按 `.omnistore/` 文件名批量删除。设置过期的图不能发比剩余保留期更长的显式 freshness；已进入客户端的缓存无法即时撤回。长期不可变原图和路径可覆盖的静态资源使用不同缓存策略。
