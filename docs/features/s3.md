# S3 兼容接口

## 1. 定位

OmniStore 提供面向已有工具的 S3 兼容访问层，不定位为完整 AWS S3 实现。

Storage Source 仍是本地真实目录。

## 2. Endpoint

S3 可以使用独立监听端口，默认显式开启后运行。

路由使用 Path-style：

```text
/{storage_key}/{object_key}
```

不支持 virtual-host-style。

## 3. 鉴权

AWS Signature V4。

支持：

- Authorization Header；
- Presigned URL；
- 时间偏差检查；
- 需要的 aws-chunked/trailer 兼容语义。

凭据使用独立 Access Key / Secret Key。

## 4. 当前对象操作

包含：

- Bucket 列举/检查；
- ListObjectsV2；
- HEAD Object；
- GET Object；
- PUT Object；
- DELETE Object；
- 批量 Delete；
- Multipart。

所有对象操作映射回 Storage Source 相对路径并经过权限/安全检查。

## 5. Multipart

支持：

- CreateMultipartUpload；
- UploadPart；
- ListParts；
- CompleteMultipartUpload；
- AbortMultipartUpload。

Part 位于：

```text
{data.dir}/tmp/multipart/{upload_id}/
```

不污染 Source。

Upload 超时/孤儿临时数据按系统 GC 规则清理，但必须跳过 recovery 仍持有的状态。

## 6. Crash Recovery

UploadPart 覆盖和 Complete 都有独立恢复语义。

最终对象、Multipart ETag、Upload/Part DB 状态之间必须按提交边界恢复，不能出现对象已经发布但元数据不可判断的情况。

## 7. 兼容策略

不追求 AWS API 覆盖率。

优先验证：

- AWS CLI；
- rclone S3；
- s3cmd；
- MinIO Client。

真实失败 → 修协议差异 → 增加回归测试。
