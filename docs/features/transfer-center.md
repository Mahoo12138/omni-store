# 文件中转

> 修订：2026-10-05。本文记录当前发送、收集、收发记录与公开链接流程；接口细节见 [API](../API.md)，权限与存储边界见 [设计](../design/transfer-center.md)。

文件中转用于临时发送一批文件，或收集别人提交的文件。公开入口 `/transfer` 直接提供「发送文件」「收集文件」「收发记录」三个 outline Tabs，与工作台 `/app/transfer` 共用同一套任务界面。公开网盘、图床和公共导航提供入口。

## 入口与记录

发送页可选择本地多个文件或文件夹，再设置标题、留言、有效期、密码、取件码和下载次数。收集页设置标题、说明、有效期、访问验证、姓名/留言要求、扩展名与大小限制。创建后显示分享链接；收集者可进入记录查看提交。

任务详情具有可直接打开、刷新与回退的地址，例如：

```text
/transfer?view=send
/transfer?view=collect
/transfer?view=history
/transfer?view=history&record=send&id=123
/transfer?view=history&record=collect&id=456
```

`/app/transfer` 支持相同查询参数。详情根据任务 ID 请求所有者接口，不依赖最近 200 条记录中是否包含该任务。记录与管理在页面内呈现，不通过嵌套弹窗展开。

分享链接直接进入对应公开页面：

```text
/pickup/{publicKey}
/collect/{publicKey}
```

这些页面不要求先回门户粘贴链接，也不提供短码搜索。姓名和留言仅是任务内容或提交信息，不作为身份凭据；当前按访客身份管理记录，不提供邮箱字段、邮件通知、邮箱恢复或跨设备恢复。

## 访客与登录身份

访客可创建、上传和管理自己的中转任务，并在同一浏览器中查看收发记录。中转访客身份使用独立 Cookie，与普通应用登录会话分开；清除 Cookie、身份过期或更换设备后，无法依靠任务标题、姓名或邮箱恢复所有者权限。公开分享链接仍按任务自己的状态与访问规则处理。

访客界面提供 1 天有效期。任务最晚在访客身份截止时间结束；单个访客最多 20 个活跃任务、1 GiB 活跃载荷，单文件也不高于 1 GiB，并受上传配置、站点中转配额和存储源更小的配额限制。访客身份有效期不超过配置的 Web 会话期限和 7 天中的较小值，身份限制由接口返回；实际剩余空间仍在写入时校验。

登录用户的任务归当前账号所有。从已有网盘文件创建快照、将收到的提交保存到普通存储源，需要真实登录与相应目录权限。访客中转 Cookie 不授予普通文件管理、存储源或应用管理权限。

## 发送文件

1. 创建发件包草稿，选择本地文件/文件夹；登录用户也可从有读取权限的网盘目录复制文件。
2. 保留各文件的相对路径逐个上传。失败文件可重试；全部完成后才能定稿。
3. 定稿后成为可公开领取的发件包，生成分享链接。设置了取件码时，仅在创建响应中展示一次明文码。
4. 接收者打开链接，验证后查看文件列表，下载单文件或全部 ZIP。当前公开取件界面不提供在线预览。

网盘来源采用独立快照。原文件随后移动、删除或修改，不会改变已复制的中转载荷；中转过期也不删除原文件。定稿后的载荷不能通过普通文件管理器修改。

发件包状态为 `draft → active → expired/revoked`。撤销停止领取并删除载荷，记录仍可用于查看任务状态。下载次数由服务端原子预占；一次文件下载或 ZIP 请求各消耗一次，失败或中断的下载不会自动返还次数。

## 收集文件

收集者可以设置姓名和留言是否必填、允许的扩展名、单文件上限与任务累计收集总量上限。后者针对该任务所有提交的累计载荷，不是每次提交单独重置的限额。

访客打开收集链接后使用宽上传区选择多个文件、文件夹或拖放文件。文件夹层级保留；选择会累加到当前批次，可逐个移除。页面检查重复路径、允许类型和单文件大小；服务端仍负责最终约束、任务总量与配额校验。

姓名、留言与已选文件在提交或重新验证失败后保留。成功后展示本次提交的文件数量与大小，并可继续提交另一批。重新打开另一个 publicKey 时，访问会话与上传草稿都重新初始化。

提交者只能提交自己的批次，不能列出、读取或删除其他人的提交。所有者的收件记录按提交者与批次展示文件，可下载；登录所有者还可以复制到有写权限的普通目录。复制不会删除原提交，原件仍按收集任务的生命周期保留。

收集任务状态为 `active → closed/expired/revoked`。关闭后停止新提交，所有者仍可查看已有提交；公开页明确说明无法继续提交。

## 可选访问验证

网页新建任务默认 `require_code=false`，可单独开启取件码/收件码，也可单独设置密码；两项同时设置时都须验证。未设置两项时，直接打开高熵分享链接即可进入内容流程，页面自动请求任务访问会话。访问会话通过 Bearer 头携带，不放入链接。

API 创建时省略 `require_code` 仍等同于 `true`。`v2.0.2` 迁移为历史任务设置 `require_code=true`，保留原来的短码保护，不能用新界面的默认值推断旧任务是否需要验证。关闭短码时创建响应中的 `pickup_code` / `code` 为空；历史列表和详情不重新返回明文短码。

访问会话有期限，也受任务自身截止时间约束。失效后重新确认任务状态；任务仍有效时重新验证，无需清空收集草稿。已关闭、过期或撤销的任务不会通过重新验证恢复。

## 存储与站点服务

管理员在站点配置中为 `transfer_center` 绑定存储源并设置中转活跃载荷配额与默认有效期。载荷位于绑定源的 `.omnistore/transfer/` 内部命名空间。

每个任务保存创建时的源 ID。换源只影响新任务；关闭或解绑站点服务会阻止创建新任务，已有任务依照自身状态、原始存储源可用性和访问会话继续处理。公开系统状态中的 `transfer_center.enabled` 表示当前新任务服务实际可用，不代表所有历史链接的状态。

清理由任务记录证明载荷归属，再处理过期、撤销和遗留草稿。它不扫描或删除普通博客静态目录。收集文件保存到静态发布目录后，副本可能公开；访问权限仍由目标目录与静态 HTTP 配置决定。
